# 发布检查

这份清单区分公开源码与分发桌面二进制。README 和 MIT 文件就绪，不代表已经创建仓库、发布版本或完成全部第三方许可核验。

## 公开源码

- [ ] 确定 GitHub 仓库名称、所有者和可见性。创建仓库、首次提交及推送分别按实际授权执行；不要从个人工作区整体上传。
- [ ] 保留 `LICENSE`、`THIRD_PARTY_NOTICES.md` 和 `docs/shadcn-LICENSE.md`；包元数据声明 MIT，`private: true` 只限制误发到 npm，不阻止 GitHub 开源。
- [ ] 检查实际提交清单，而非只检查 `.gitignore`。个人文库 `data/`、图片 `pictures/`、`release/`、依赖、日志、环境文件、私钥、凭据和本地备份不得进入公开提交。
- [ ] 已跟踪文件不受新增忽略规则追溯保护。当前本地扫描不能代替提交清单与未来远程历史检查；命中项只记录路径和行号，不粘贴秘密值。
- [ ] 确认测试里的票据和链接只是测试值，文档和截图没有私人文章、账号资料或个人绝对路径。README 演示来自隔离测试文库。
- [ ] 保留解析器来源注释和第三方许可，不将第三方依赖统一重许可为 MIT。
- [ ] 从独立干净副本安装锁定依赖、构建、类型检查和离线测试，确认 README 的入口可用。不用旧 `node_modules/` 或作者文库证明新用户能启动。
- [ ] 双语 README 的命令、版本、配置项和限制一致；仓库地址确定后再添加真实下载入口，不放虚构的 Release 链接或徽章。

## 桌面二进制

- [ ] 在 Windows x64 构建便携目录，核对随包 Node、原生 SQLite 和程序版本。完整解压使用，不只发布单独的 `拾页.exe`。
- [ ] 检查分发目录未包含作者数据、会话、本机文库绑定或测试资料；用独立新文库完成启动与退出验证。
- [ ] 核对分发目录包含项目 `LICENSE`、第三方声明及实际分发组件要求的许可全文/NOTICE，包括编译进前端的依赖；项目许可与 Electron 根目录的许可分别保留。
- [ ] 保留 Electron 的 `LICENSE`、Chromium notices，以及随包 Node 的 `LICENSE`。后端依赖自带的许可文件和编译进前端的代码均需检查；只附许可证名称表不够。
- [ ] 为最终压缩包记录摘要，并在实际 GitHub Release 中说明平台、版本、完整解压方法、未签名状态及已知限制。

## 已知限制与报告

打包时 `scripts/package-licenses.mjs` 从已安装的生产依赖及 Tailwind CSS 收集许可全文和 NOTICE，写入便携目录的 `licenses/` 与 `licenses/manifest.json`。项目 MIT 写为 `LICENSE.shiye`，不覆盖 Electron 的 `LICENSE`；Node 和 Chromium 的声明保留原位置。缺少依赖、许可正文、空文件或越界来源会让打包失败。只有明确版本的上游补充可用于缺少许可文件的 npm 包，来源随清单记录。`test/package-licenses.test.ts` 覆盖传递依赖、嵌套版本、NOTICE、运行时许可保留及失败路径。

微信清单使用非公开接口，不能保证任意公众号完整历史或长期无人值守。测试与演练不访问真实微信，也不能证明物理断电安全或大附件吞吐。

SQLite 临时文件的创建进程仍未归因，文件变化可能触发保护性中止。报告问题时提供应用版本、Windows/微信版本、执行的操作和脱敏错误；不要提交数据库、个人图片、完整会话URL或票据。

发布前检查不要求新增安装器、自动更新、云服务或CI。先公开可复现的源码和清楚的限制，再依据实际反馈决定后续工作。
