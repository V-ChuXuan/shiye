# Windows桌面版

识别关闭、原生文库取消与窗口状态记忆契约见[退出与操作完善](safe-cancel-reader.md)。取消在安全检查点生效，保留原件和未完成标记；窗口偏好独立于文库绑定。

文库维护结束后会重新检查当前自有后台的停止状态，按原生提示手动恢复；退出确认未结束时不叠加恢复提示，不自动解锁或继续采集。

0.1.1增加当前界面的原生异常恢复；明确重载只恢复受控本地页面，后台服务及采集保持。无响应可继续等待，服务同时停止时沿既有服务恢复，不自动解锁。行为与验证见[阅读和桌面收尾契约](library-polish.md)。

双击`release/拾页-win32-x64/拾页.exe`。整个文件夹是一份应用，包含Electron、后端、Node和SQLite原生模块，不要单独移动exe。第一版是Windows x64便携目录包，没有安装器、代码签名或自动更新。

## Windows 启动入口

- **触发与签名：**双击项目根目录的 `启动拾页.bat`，工作目录固定为脚本所在目录，支持中文和空格路径。
- **行为：**已有 `release/拾页-win32-x64/拾页.exe` 时优先打开桌面程序，不安装源码依赖、不构建、不打开浏览器；未打包时明确提示并沿用源码浏览器启动流程。启动器不承担文库锁恢复、进程清理或自动采集。
- **格式与校验：**批处理为无 BOM 的 UTF-8，使用 CRLF，先执行 ASCII 代码页切换再处理中文。`.gitattributes` 仅为批处理固定检出 CRLF，不改变 PowerShell 脚本编码。缺少 Node 或安装、构建、启动命令失败时，保留失败提示并暂停，返回非零状态。
- **用例与测试：**`test/launcher.test.ts` 在中文空格临时目录通过真实 `cmd.exe` 执行脚本，覆盖桌面优先、源码成功及失败分支；替身命令不连接微信、不打开真实浏览器或用户文库，并断言批处理换行和 Git 属性。
- **错误与正确：**不能把 UTF-8 批处理的 LF 文件直接当作双击可用的 Windows 入口，也不能只校验文本内容；应保持 CRLF 并在真实命令解释器中核对执行分支和退出码。

窗口右上角关闭会隐藏到托盘；单击托盘恢复，右击选择「退出拾页」停止自己的服务。若窗口连接的是已运行的同一文库服务，退出桌面保留那个服务。托盘还可打开图片和文库文件夹。

## 1. 范围与触发

复用现有React/Fastify/SQLite，不新建业务层。Electron主进程只管理窗口、托盘和子进程；renderer无Node和通用文件/shell接口。

## 2. 签名

- `npm run desktop`：开发窗口，需要先build及准备随包Node。
- `npm run desktop:package`：在Windows x64构建并生成便携目录。
- `npm run test:desktop`：运行真实exe，在隔离文库验收，不请求微信。
- `拾页.exe --library-root=<绝对目录> --user-data-dir=<绝对目录>`：可选本机启动参数；配置文库后记住位置。
- 内部Node IPC：`{type:'ready',port}`、`{type:'shutdown'}`；没有公开HTTP关闭接口。

## 3. 契约

新用户默认`app.getPath('userData')/library`，数据库和封面在`data`，正文图默认`pictures/公众号名/文章标题`。软件升级只换程序目录，勿删除文库。图片位置可在设置更改，默认不迁移，显式迁移仍沿用原契约。配置文件`library.json`只保存文库根，不保存微信会话。

已有文库可通过`--library-root`传入其绝对路径进行绑定，成功打开后记住位置；未指定时按新用户默认位置创建文库。此参数没有作者机器路径的硬编码。读取4387的health标识和settings.dataDirectory都匹配才复用；否则在随机回环端口启动自有子服务。Web与桌面在打开数据库前取得`data/.shiye-service.lock`；活进程或未知锁拒绝。异常退出遗留的锁不自动删除，以免多个恢复进程误删对方的新锁；提示用户确认所有拾页进程退出后再清理这个锁文件。正常退出释放自有锁/服务，父进程失联也关闭子服务。

打包固定Electron45.0.0、Node24.22.1、packager20.3.0。Node从[官方发行站](https://nodejs.org/dist/v24.22.1/)取得并核对SHA256，许可证来自官方源码tag。SQLite在随包Node下进行内存建表/写读检查；不使用Electron ABI加载现有Node模块。原生ABI边界见[Electron文档](https://www.electronjs.org/docs/latest/tutorial/using-native-node-modules)。

renderer开启sandbox/contextIsolation，关闭nodeIntegration，拒绝权限和下载；只加载本机同源主界面。内部导航是按钮，保留页面路由状态，不向用户显示回环URL目标。图片只在现有窗口Dialog内按适配或原图尺寸查看，不再允许本地资源另开窗口，也不允许API地址替换主界面。

所有新窗口请求均拒绝。外部只允许`https://mp.weixin.qq.com/s...`公开文章，以及关于页五个确定的GitHub项目地址，交系统浏览器；没有任意URL或文件打开接口。允许的致谢路径为`shadcn-ui/ui`、`lucide-icons/lucide`、`pmndrs/zustand`、`motiondivision/motion`、`bvaughn/react-resizable-panels`，拒绝子路径、查询参数、伪造域名、凭证和非标准端口。打开失败有可见错误，不保留未处理的Promise异常。

## 4. 校验与错误矩阵

| 情况 | 结果 |
|---|---|
| 同一应用第二次启动 | 唤回原窗口，新进程退出 |
| 文库被另一个服务使用 | 不打开第二个数据库，提示退出原程序 |
| 未知/损坏锁 | 保留锁并提示，不擅自删除 |
| 缺Node或后端 | 可见启动错误并退出，提示完整解压 |
| 本地服务启动失败或超时 | 关闭自有子进程，不加载假成功页面 |
| 外部file/非白名单URL | 拒绝打开 |
| 本地图片window.open/API顶层跳转 | 不创建窗口，不替换主界面 |
| 微信验证/会话过期 | 继承现有停止和重连语义 |

## 5. 正常、基本与错误用例

正常：双击应用→加载文库→选文章→采集→离线阅读→关闭到托盘→退出。基本：新文库为空，可添加公众号；不自动采集。错误：第二进程打开同库不能恢复正在运行的任务，必须拒绝；复制新程序目录不能复制旧用户数据进去发布。

## 6. 测试要求

`desktop.test.ts`锁和URL/路径边界；`desktop-smoke.mjs`实际包启动、Unicode文库、SQLite、页面、沙箱、所有资源新窗拒绝、API顶层导航拒绝、受控外部打开、单实例、托盘/恢复、退出释放、记住位置、复用服务不误杀、缺运行文件错误。外链自动测试替换shell.openExternal，只检查真实调用参数，不启动系统浏览器。报告在`data/desktop-verification/`，不进入发布包。发布包不含真实data/pictures/截图/日志，包检查断言这些目录不存在。

## 7. 错误与正确做法

错误：用Electron重编译项目SQLite，然后让普通Node加载；或退出时按端口杀所有同名进程。正确：独立随包Node复用其ABI，只关闭本应用fork并持有的子服务。外部服务复用与拥有退出权是两回事。

## 文件夹选择

图片位置和旧版资料迁移共用现有目录选择API，Windows原生Common Item Dialog以FOS_PICKFOLDERS模式显示地址栏、搜索及文件夹列表，替代旧目录树。随包脚本UTF8 BOM兼容WindowsPowerShell5，选择只回填输入，取消不改变草稿或保存位置；中文/空格路径、取消、不存在初始目录及原生窗口形态由隔离验收验证。保留手动路径输入，不引入新依赖、Electron IPC或通用文件访问。

## 完整文库备份与恢复

在系统托盘右键或按Alt打开应用菜单，选择“备份文库…”或“恢复文库…”。备份选择存放父目录后生成独立子目录，包含数据库、多处已登记图片及本地缓存。需要暂时停止本应用自己的服务，完成或失败后重新启动；微信连接会失效，之后按需要重新连接。不允许在有活动任务或使用其他进程服务时关闭服务备份。

恢复依次选择完整拾页备份和新文库存放父目录，只创建新的文库子目录，校验成功后可选择打开。原文库及备份保持不变；旧版archive导入不是这种备份恢复。恢复账号为手动更新、未连接，任务不自动继续。恢复目标不能是现有文库，不能覆盖其他文件，失败目录保留为未完成状态，不显示成功。

备份格式为shiye-backup.json v1完成清单及有摘要的数据库/图片文件。不要只复制pictures作为完整文库备份；切换过保存位置的文章可能来自多个根。桌面操作沿用随包Node24，SQLite不在Electron进程加载；主进程管理工作进程和窗口，renderer无通用文件接口。

完成清单的UTF-8大小最多16 MiB，备份和恢复使用同一上限；这不是图片总大小限制。超限时显示失败，原文库保留，不发布完整备份。失败目录中的未完成标记不可手动移除后当作完整备份使用。

备份/恢复开始后，主窗口标题和Windows任务栏显示进行状态；校验、数据库、图片、封面与发布阶段分别反馈，数字为当前阶段处理项计数，校验同一文件的摘要和图像结构可分别计项。复制完成不代表已发布，发布前任务栏不会显示完整100%；重开原库期间仍显示进行状态，终态提示前清除，finally兜底恢复「拾页」。取消选择同样清除。进度沿既有Node worker单向IPC传递，主进程严格校验phase、整数范围、消息字段及工作进程生命周期，拒绝无效或迟到消息，不增加renderer接口。完整结构见contracts.md。

打包可复用已有官方运行时缓存，但必须核对版本、官方来源记录、SHA256、许可证和实际Node版本；缺失或不匹配才重新下载并核验。复用缓存不冒充当次在线校验。

## 异常启动恢复

同库锁在SQLite开库前检查。`LibraryStartupError.code`限定为`library_in_use`、`library_lock_unknown`、`library_lock_stale`、`library_incomplete`，sidecar仅沿既有error消息传递类别与安全提示。主进程按类别显示原生恢复引导，允许打开已绑定文库目录、重新检查或退出；重试须先等待失败的自有sidecar退出，不添加renderer文件权限。

活跃进程不删除锁，未知锁不猜测，遗留锁展示确认退出所有拾页后处理的步骤，未完成恢复不能通过重试删除标记。普通缺程序文件错误仍显示原启动错误；不能把任意包含“锁”的异常误当可恢复类别。隔离原生烟测覆盖四类错误、打开目录、重复检查、退出与锁/数据库/标记原样保留。

桌面sidecar端口每次由系统分配，阅读位置通过本库API持久化，不能把同一origin刷新验证冒充跨应用重启验证。实际程序烟测在前后两次服务origin下读取相同文章两视图位置。

## 启动取消与超时收束

同库锁覆盖初始化、运行及关闭全过程。shutdown或父进程断连发生在取锁、创建Fastify或listen期间时，先收束正在进行的初始化，再关闭应用，最后单次释放锁并断IPC；不能在app尚未赋值时提前放锁。

主进程启动失败或20秒超时只能处理该次fork捕获的自有子进程，请求其停止并等待退出/关闭后才返回错误；不将全局child的后续实例当作失败进程清理，不取得外部服务退出权。迟到ready或error不能恢复已取消的启动。备份文件已完成但服务无法重新打开时，保持可见错误和完整备份路径，不误报当前文库服务已恢复。

验收覆盖初始化各阶段关闭、关闭顺序与单次放锁、超时和迟到ready、fork失败收尾、备份重启失败及实际隔离进程退出后锁/端口释放；只用可控进程和临时文库，不停用户服务作实验。

## 文库绑定损坏与原子保存

### 范围与签名

`desktop/config.cjs`提供`readLibraryRoot(file)`、`existingLibrary(root)`和`saveLibraryRoot(file, root, issue?)`。只管理主进程的`userData/library.json`，不增加renderer接口。读取返回已有文库绝对根，只有读取配置本身报ENOENT才返回undefined；其他读取、格式或已有库校验错误抛出`library_config_invalid`。

### 契约

已记住的根及恢复选择必须有可读的`data/archive.sqlite`普通文件；实际数据库能否打开仍由Node服务验证。坏记录原字节随错误保留在内存，无法读取时不猜测内容。主进程用原生窗口提供“选择已有文库”或“退出”；取消不打开默认库、不保存。服务成功打开后，保存新绑定前校验坏记录未变化并以`library.json.invalid-<UUID>`保留副本；不可读、保留失败或已变化均停止保存。显式`--library-root`是已有授权选择，不重复弹出选择窗口，坏记录保留要求相同。

启动、切换和失败回退共用保存入口：同目录唯一`wx`临时文件，写入、fsync、关闭后rename替换。失败保留原绑定，仅清理本次创建的临时文件；不是完整断电一致性或多程序并发编辑保证。恢复、换库不自动连接微信或继续采集。

### 校验与错误矩阵

| 输入或事件 | 结果 |
|---|---|
| 配置不存在 | 首次启动默认库，服务成功后记住位置 |
| 配置损坏、根非法、原库不存在/不可读 | 原生重选或退出，不静默切换空库 |
| 重选取消或新库服务打开失败 | 原记录不变，不保存新绑定 |
| 原配置无法读取或保存前已变化 | 不覆盖，显示错误并退出 |
| 临时写入、刷新、替换失败 | 原记录不变，清理自己创建的临时文件 |
| 已重选且服务成功 | 保留坏记录副本，再原子保存新绑定 |

### 用例与测试

基本用例是首次启动和正常记忆重开；正常恢复用例是损坏JSON后选回已有库；错误用例包括取消、权限错误、空/非法根、原库消失、坏记录被外部修改和写入失败。`test/library-config.test.ts`断言原字节、副本、默认库未打开及临时文件清理；桌面VM测试覆盖调用路径、回退与新服务失败不保存；`scripts/desktop-smoke.mjs`用隔离profile运行桌面程序，验证选择/取消结果和重新打开的实际数据根。

### 错误与正确做法

错误：捕获所有读取错误后直接使用默认库，再覆盖library.json。正确：区分首次启动与损坏绑定，保留原记录，让用户通过原生选择恢复；只有服务打开成功才保存。

## 运行中服务意外退出

### 1. 范围

只有已ready且由当前桌面持有的sidecar意外退出，才提供原生“重新打开文库”或“退出”选择。点击重新打开后沿既有服务和锁检查打开当前绑定文库；不更改绑定、不自动连接微信或继续任务。若留下遗留/未知/活跃锁，继续原分类引导，不自动删除锁。复用的外部服务不取得退出权。

### 2. 签名

主进程`recoverService(owned)`由`startService`的ready后exit调用；重试复用`loadLibrary(root)`、`service`及`stopService(owned)`。不新增renderer IPC、文件权限或环境变量。

### 3. 契约

恢复过程单实例互斥，重复退出事件、正在维护或退出时不重复启动；迟到的对话响应不能替换已切换的新服务。失败保留明确错误和再次选择，不无限自动重试；终态清理临时进度。用户选择退出可正常结束，不被恢复互斥阻止。VM及隔离桌面回归覆盖ready后退出、重试成功/失败/取消、重复/迟到事件、维护和退出互斥、锁/数据/阅读位置保护。

### 4. 校验与错误

| 事件 | 行为 |
|---|---|
| ready前失败 | 保留既有启动错误/锁引导 |
| 自有ready服务退出 | 原生等待明确重开或退出，无自动fork |
| 维护、退出、旧child或重复事件 | 不创建重复恢复流程 |
| 重开失败或页面加载期间再次退出 | 再次等待明确选择，清理暂态反馈 |
| 遗留、未知、活跃锁/未完成文库 | 沿既有分类引导，原件保持 |
| 选择退出或晚到响应 | 正常退出，晚到响应不能重开新服务 |

### 5. 用例

基本为持有服务正常退出；正常恢复为用户点击后同窗重开原库；异常为重开失败、重开就绪后再次退出及遗留锁。

### 6. 测试

`test/desktop-library.test.ts`覆盖互斥和失败时序；`scripts/desktop-recovery-smoke.mjs`用隔离portable实际child验证明确选择、单窗、阅读位置/暂停任务和账号断开，以及强制退出后锁/数据库/图片不变。原生对话返回由测试替身控制，不操作用户文库。

### 7. 错误与正确

错误：任意服务退出后自动重启、解锁并继续采集。正确：只处理自己持有的服务，明确点击后重开当前根，锁与采集仍遵守既有规则。
